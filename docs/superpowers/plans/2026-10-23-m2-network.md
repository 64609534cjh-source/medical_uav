# M2 Neural Network Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Policy/value networks (MLP and set/attention) that PPO can reuse, trained by behaviour cloning from Slack-aware, two new baselines, a shared evaluator, an M2 demo, and the M2 submission package.

**Architecture:** A new package `medical_uav/agents/` holds the networks, the network policy wrapper and behaviour cloning. Baselines stay in `medical_uav/baselines/heuristics.py`. Scripts drive training (`train_bc.py`), evaluation (`evaluate.py`, internal) and the demo (`demo_network.py`). Small BC checkpoints are committed under `checkpoints/` and ship with the submission.

**Tech Stack:** Python 3.11.17, PyTorch 2.14.1 (CPU wheel), NumPy, Gymnasium, pytest.

**Spec:** `docs/superpowers/specs/2026-10-23-m2-network-design.md` (extends `docs/superpowers/specs/2026-10-10-medical-uav-design.md`; baseline rules in its §9).

## Global Constraints

- Branch `m2-network`; merge to `main` only with all tests passing; tag `m2-submission-v1` on `main` at submission. Commit messages have no co-author trailer.
- Own PyTorch code, no RL library. Lean, readable code; short programmer-style comments; no defensive checks beyond the spec's assertions.
- Observation `[B, 403]` = global 31 | 12 pending slots × 27 | 3 cargo slots × 16 (`GLOBAL_DIM`, `PENDING_DIM`, `ONBOARD_DIM`, `N_SLOTS`, `N_ONBOARD` from `observation.py`/`actions.py`/`config.py`); feature 0 of each slot is its occupied flag. Actions: 26, layout from `actions.py` (`PICK0=0`, `DELIVER0=12`, `CHARGE0=18`, `RETURN=24`, `WAIT=25`).
- Invalid actions: logits set to `-1e9` before softmax.
- BC: teacher Slack-aware; Adam `3e-4`, batch 256, at most 20 epochs; split by whole episodes 80/20; cross-entropy on the teacher action only (value head not trained by BC).
- BC data: loads low/medium/high × demand seeds 0–333 (1,002 episodes, training range). All M2 numbers on dev seeds `DEV_SEEDS` (100000–100039); `TEST_SEEDS` untouched.
- `torch==2.14.1` pinned in both `environment.yml` (pip section) and `requirements.txt`, with `--extra-index-url https://download.pytorch.org/whl/cpu` so Linux/Windows get the CPU wheel and macOS the PyPI wheel.
- The M2 demo runs on CPU in a few minutes, from any working directory.
- Submission zip = `git archive` of the tag + report PDF; `docs/`, `tests/`, `scripts/calibrate.py`, `scripts/headroom.py`, `scripts/evaluate.py`, `scripts/reward_screen.py` export-ignored.

## Review Focus

- A state where only WAIT is valid: the network policy returns WAIT and the masked probabilities sum to 1 (Task 4).
- A batch of one observation: `value` has shape `[1]`, logits `[1, 26]` (Tasks 2, 3).
- A checkpoint saved after GPU training loads on a CPU-only machine and reproduces the outputs (Task 4).
- A policy that returns an invalid action during evaluation: the evaluator raises instead of letting the environment silently run WAIT (Task 5).
- `demo_network.py` started from another directory still finds the checkpoints (Task 7).
