# M2 Neural Network Implementation Plan (v2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Environment v2, policy/value networks (MLP and set/attention) that PPO reuses, behaviour cloning from Slack-aware, two new baselines, a shared evaluator, the M2 demo and package; then production PPO run end to end on a separate branch.

**Architecture:** Environment v2 changes stay inside `medical_uav/env/` and `medical_uav/splits.py`. A new package `medical_uav/agents/` holds networks, the network policy wrapper, behaviour cloning and (Part C) PPO. Scripts drive training (`train_bc.py`, `train_ppo.py`), evaluation (`evaluate.py`, shipped) and the demo (`demo_network.py`). Small checkpoints are committed under `checkpoints/`.

**Tech Stack:** Python 3.11.17, PyTorch 2.14.1 (CPU wheel), NumPy, Gymnasium, pytest.

**Spec:** `docs/superpowers/specs/2026-10-23-roadmap-to-final.md` (governing) and `docs/superpowers/specs/2026-10-23-m2-network-design.md`; baseline rules in `docs/superpowers/specs/2026-10-10-medical-uav-design.md` §9; pilot code for reference in `docs/superpowers/experiments/2026-10-23-pilots/`.

## Global Constraints

- Parts A–B on branch `m2-network`, merged to `main` when tests pass; tag `m2-submission-v1` on `main` at submission. Part C on branch `m3-ppo` (from `m2-network` after Task 5), not in the M2 submission. Commit messages have no co-author trailer.
- Own PyTorch code, no RL library. Lean, readable code; short programmer-style comments; no defensive checks beyond the spec's assertions.
- Observation `[B, 452]` = global 80 | 12 pending slots × 27 | 3 cargo slots × 16 (constants `GLOBAL_DIM`, `PENDING_DIM`, `ONBOARD_DIM` from `observation.py`, `N_SLOTS` from `actions.py`, `N_ONBOARD` from `config.py`); feature 0 of each slot is its occupied flag. Actions: 26 (`PICK0=0`, `DELIVER0=12`, `CHARGE0=18`, `RETURN=24`, `WAIT=25`).
- Reward v2: +1 on time, +0.1 late, −0.1 per expired order, −0.001 per battery % used. Version string `ENV_VERSION = "v2"` recorded in every checkpoint and result file.
- Invalid actions: logits set to `-1e9` before softmax; evaluation and PPO assert no invalid action is chosen.
- Seeds (`splits.py`): `SCREEN_SEEDS` 100000–100039, `SELECT_SEEDS` 100040–100139, `TEST_SEEDS` 200000–200299, `TRAINING_SEEDS = (11, 22, 33, 44, 55)`; demand seeds for training in [0, 100000). All M2 numbers on `SCREEN_SEEDS`.
- BC: teacher Slack-aware; 900 episodes = demand seeds 0–299 × loads low/medium/high; split 80/20 by demand seed; Adam 3e-4, batch 256, ≤ 30 epochs, best validation loss kept; masked cross-entropy only (value head not trained by BC).
- PPO (Part C), from the pilot exactly: 16 envs × 128 decisions, 4 epochs, minibatch 512, clip 0.2, Adam 3e-4 (eps 1e-5) linearly decayed to a 5 % floor, entropy 0.01 decayed to a 10 % floor, GAE λ 0.95, γ 1, reward ÷ 10, advantages normalised per minibatch, gradient clip 0.5, loss = policy + 0.5 × (0.5 × MSE) − entropy term; load drawn uniformly per episode.
- `torch==2.14.1` pinned in `environment.yml` (pip section) and `requirements.txt` with `--extra-index-url https://download.pytorch.org/whl/cpu`.
- The M2 demo runs on CPU in a few minutes from any working directory.
- Zip = `git archive` of the tag + report PDF; `docs/`, `tests/`, `scripts/calibrate.py`, `scripts/headroom.py` export-ignored; `scripts/evaluate.py` shipped.

## Review Focus

- A state where only WAIT is valid: the network policy returns WAIT and the masked probabilities sum to 1 (Task 5).
- A batch of one observation: `value` has shape `[1]`, logits `[1, 26]` (Tasks 3, 4).
- A checkpoint saved after GPU training loads on a CPU-only machine and reproduces the outputs (Task 5).
- A policy that returns an invalid action during evaluation: the evaluator raises instead of letting the environment silently run WAIT (Task 6).
- `demo_network.py` started from another directory still finds the checkpoints (Task 8).
