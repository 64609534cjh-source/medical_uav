`medical_uav/agents/networks.py` holds both networks behind one interface: a batch of observations [B, 452] and action masks [B, 26] go in; action logits [B, 26] and state values [B] come out. Before returning, the logits of actions the mask forbids are set to −10⁹, so the softmax gives them zero probability and they receive no gradient. `split_obs` cuts each observation into its global part (80 features), the 12 waiting-order slots (27 features each) and the 3 cargo slots (16 each).

The set network (Figure 1) follows the structure in our proposal. One shared encoder embeds every order slot, another every cargo slot, and a third the global UAV state. The UAV state is the query of one four-head attention layer whose keys and values are the encoded orders, the cargo and a learned null token; empty slots are masked out, and the null token keeps the attention defined when nothing is waiting. The 64-feature UAV state and the 64-feature attention output together form a 128-feature context. A single shared scorer then gives each order its PICK logit from the order's encoding and the context, so permuting the order slots permutes the PICK logits; up to 12 waiting orders are represented. A small head gives the 14 other actions (6 DELIVER, 6 CHARGE, RETURN, WAIT) from the context, and the value head takes the context and the mean of the occupied order encodings (zero when none is waiting). The network has 62,928 parameters. As a control we also built a plain MLP: separate actor and critic, each 452 → 256 → 256 with tanh, 370,459 parameters. `policy.py` runs either network as a greedy policy and saves and loads checkpoints.
