# 实验立项与结果记录模板

> 每一个主要假设使用一份实例。未执行项写“未执行”，未知项写“待确认”，不要默认填0或填写预期成绩。

- Experiment ID / Issue / 分支：
- Owner / Reviewer：
- 假设（一句话，可被实验否定）：
- 类别：A同任务方法 / B信息接口 / C目标 / D在线计算 / E泛化 / O诊断上界
- 相对哪个冻结基准：
- 唯一主要变化：
- 若存在多个变化，为何无法拆分、需要哪些对照：
- 预计可能失败的原因：

## 2. 信息与任务合同

- map / demand generation / capacity / energy / service / termination：
- observation/action/mask schema 与 hash：
- 候选数及排序规则：
- Actor可见字段：
- Critic可见字段：
- Planner可见字段：
- 是否使用隐藏订单、真实未来、需求日seed；若是，仅允许明确标记为oracle诊断：
- reward定义、γ、GAE λ与时间尺度：
- 训练目标与评估目标是否一致：
- 如改变任务/目标，原任务指标怎样保留：

## 3. 预算与随机性

- 真实训练 transitions：
- 训练seed与独立RNG规则：
- rollout规模、epochs、minibatch、实际optimizer steps：
- 学习率完整schedule与预设总预算：
- 模仿示范/预训练样本与计算量：
- 在线规划模拟次数、情景数、时域与回退条件：
- solver预算与终止状态（如适用）：
- 所有超参候选数与失败run的登记位置：

## 4. 数据与选择

- Train清单/范围及hash：
- Dev-tune清单及hash：
- Dev-confirm清单及hash：
- 历史Test全部标记已曝光，不作新方法选择：确认/未确认
- 新Final-Test清单hash、生成规则及解封者：
- checkpoint评估频率（不得为新方法增加选择机会却不披露）：
- checkpoint选择规则与tie-break：
- 演示模型选择规则：
- 最终primary candidate与secondary candidates：

## 5. 主要指标与护栏

- 主指标：三档负载逐日准时率等权平均（变更则明确说明）。
- 辅助指标：reward、送达/过期、取货后过期、各类型计数与准时率、等待/充电/飞行。
- 类型无订单时如何处理：
- 各类型服务容忍度/约束，以及可行性依据：
- 工程：非法动作、非有限数、终止、快路径等价、回退率。
- 性能：B=1和训练batch的p50/p95、线程/设备/预热/输入、完整episode耗时。
- 统计：训练seed与需求日的重采样层次、方法间配对、跨负载是否按day block重采样。
- 实践增益/非劣容忍度（实验前固定）：

## 6. 晋级与停止

- 工程验收条件：
- 短筛条件（不能自动排除慢学习候选）：
- 长程筛选条件：
- 停止条件与负结果归档：
- 何时冻结最终候选：

## 7. 运行证据

- 训练代码完整SHA：
- 推理/评估代码完整SHA：
- dirty状态（正式结果应说明）：
- config/环境/依赖/hash：
- checkpoint manifest：
- 逐日结果与训练log位置/hash：
- 审计输出与benchmark：
- 实际wall-clock与计算量：
- 与预注册计划的偏离及发生时间：
